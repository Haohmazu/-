# Class Dashboard 2.0｜班級互動儀表板

第二階段任務核心增量開發版，尚未合併到正式網站。第一階段功能保留。使用原生 HTML、CSS、JavaScript ES Modules；無後端、付費 API、執行期外部套件或字型。繁體中文介面，資料儲存在本機瀏覽器。

## 目前能做什麼

- 教師設定班級名稱，新增學生、編輯座號及選填姓名。
- 最多 50 位學生，座號 1–50 不重複；永久內部 ID 不因修改座號改變。
- 主畫面只顯示座號，姓名僅在設定視窗顯示。
- 臺灣日期與每秒同步時鐘，回到分頁立即同步。
- 驗證 → 計算下一狀態 → 寫入成功 → 更新畫面。錯誤會顯示原因。
- localStorage 存取失敗不假裝成功；格式損壞或未支援版本時鎖定寫入，不覆蓋原資料。
- 已載入頁面可斷網繼續操作。尚無 Service Worker，斷網後重新載入或首次開啟不保證可用。

新增任務範本管理、今日參與設定、單一進行中輪次、打卡／補登／取消／最近操作復原及修正紀錄。進行中任務保存名單快照，跨日不重設。水族箱與進化、課表、計時器、匯入匯出、學期及備份還原仍未完成，不應用於正式班級任務紀錄。

## Windows 11 使用方式

### 透過 GitHub Pages（使用者不需安裝程式）

1. 將本目錄完整放在你的 GitHub 儲存庫，保留 `src`、`styles` 相對路徑。現有根目錄語音網站保持不變。
2. 儲存庫 Settings → Pages → Build and deployment → Deploy from a branch。
3. 選擇你要發布的分支與 `/ (root)`，按 Save。這會發布該分支內容，應由教師或管理者確認後操作。
4. 等待 GitHub Pages 的部署完成，在它提供的網站位址後加入 `/class-dashboard-v2/`。不要使用檔案的 GitHub 原始碼網址。
5. Windows 11 用 Chrome 或 Edge 開啟，按「教師設定」，先儲存班名，再新增座號。
6. 修改座號：教師設定 → 該學生「編輯」→ 修改 →「儲存學生」。姓名選填。按關閉或 Esc 離開設定。
7. 重新整理頁面確認仍有資料。不要清除網站資料，也不要把本機自動儲存當作外部備份。

本次未代為發布或修改 Pages 設定。GitHub Pages 專案路徑相對載入可用；未實測正式部署。相同來源的其他程式可存取 localStorage，沒有真正的登入保護。

### 本機開發（可選，需要安裝 Python 3）

在 Windows 檔案總管開啟儲存庫資料夾，於位址列輸入 `cmd`，執行：

```bat
py -m http.server 8000
```

在 Chrome / Edge 網址列輸入 `http://localhost:8000/class-dashboard-v2/`。保持命令視窗開啟，結束時 Ctrl+C。不要直接雙擊 HTML（ES Modules 不適合 file://）。若在本目錄而非儲存庫根目錄啟動伺服器，路徑改成 `/`。不同埠、瀏覽器、網址來源與電腦都有獨立資料。

## 檔案與架構

- `index.html`：主畫面、教師設定與無障礙表單。
- `styles/main.css`：三區布局、平板與手機響應式設計。
- `src/app.js`：初始化與儲存介面注入。
- `src/core/model.js`：初始資料與版本常數。
- `src/core/validation.js`：完整第一階段模型驗證。
- `src/core/migrations.js`：解碼與版本入口，拒絕未支援版本，不猜測遷移。
- `src/core/store.js`：唯一命令入口、驗證、持久化、事件通知。
- `src/features/classroom.js`：班級與學生命令。
- `src/ui/controller.js`、`clock.js`：渲染、表單、通知與臺灣時鐘。
- `tests/core.test.js`、`browser.cjs`：自動化測試。
- `docs/reference-audit.md`：第一版實際原始碼調查與遷移風險。

資料鍵 `class-dashboard-v2`，目前資料版本 `schemaVersion: 2`（與產品版本 2.0 分開）。權威資料只有班級及學生；人數由學生陣列計算。`revision` 用來拒絕已知過期分頁寫入，`savedAt` 記錄最後成功提交。讀取不會自動寫回。瀏覽器寫入使用同來源 Web Locks 互斥鎖，鎖內拒絕過期 revision。需使用 HTTPS 或 localhost 與支援 Web Locks 的 Chrome/Edge；不支援時拒絕寫入。建議一次只在一個分頁編輯。

## 重複執行測試

核心測試需 Node.js 20 以上，無須 npm install：

```bat
npm test
```

瀏覽器測試：先在儲存庫根目錄啟動前述 Python 伺服器，再於本目錄執行（僅開發者需要安裝測試工具）：

```bat
npm install --no-save --package-lock=false playwright
set CHROMIUM_PATH=C:\Program Files\Google\Chrome\Application\chrome.exe
npm run test:browser
```

Edge 可改用 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`。依實際安裝位置調整。Linux 測試預設 `/usr/bin/chromium`；若伺服器路徑不同，可設定 `TEST_URL`。應用本身不依賴 Playwright。

本次結果：Node 核心測試 16/16 通過；Chromium headless 流程通過：新增、編輯、拒絕重複、重整保留、HTML 字串安全呈現、已載入後斷網儲存，以及 1920×1080、1366×768、1280×720、1024×768、390×844 無頁面水平溢出。核心測試中故意模擬渲染失敗會印出預期錯誤日誌，該案例仍驗證成功保存。未驗證 Windows 原生 Chrome/Edge、真實觸控與投影機。尺寸檢查不等於全面視覺驗收。

## 人工驗收

1. 在 Chrome 與 Edge 分別設定班名，確認兩者本機資料獨立。
2. 新增 1 號與 2 號；重複 1 號應拒絕，主畫面不出現姓名。
3. 編輯 1 號為 10 號，重新整理後應維持 10 號；設定視窗可用 Esc 關閉、Tab 操作。
4. 將瀏覽器調成上述五種尺寸與 125% 縮放，檢查文字、座號、對話框可捲動且按鈕可點擊。
5. 頁面載入後斷網，儲存新班名應成功；恢復網路後重整仍保留。
6. 切換分頁一分鐘後返回，時鐘應與臺灣時間一致。
7. 使用獨立測試瀏覽器設定檔測試儲存拒絕及損壞資料，勿使用真實班級資料；確認錯誤不會顯示成功。

### 第二階段增量驗收（Windows 11）

以開發分支啟動本機伺服器，保留前述 Windows 操作方式。教師設定新增學生，調整「今日參與」，選範本並開始任務。關閉設定後點座號打卡。返回設定可補登、取消及復原最近一次打卡。重新整理仍保留名單與進度；修改今日參與不影響本輪。取消任務會保留歷史。達到門檻目前只顯示提示，不發魚、不自動完成或開始下一輪。

重跑 `npm test` 與 `npm run test:browser`。任務瀏覽器測試另覆蓋開始、打卡、重複拒絕、重整、取消、復原及過期分頁寫入拒絕。第二階段仍需補進行中參與名單明確修訂與完整統計；第四階段才加入 COMPLETED 與原子進化結算。尚無外部備份功能，請使用測試資料。
